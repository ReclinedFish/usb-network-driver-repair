# Privacy and Publication

The source code is generic. It does not contain a device-specific serial number,
user profile path, MAC address, Wi-Fi password, access token, or bundled driver.
It makes no network requests and does not upload telemetry.

## What Stays Local

Ordinary inspection output and repair snapshots can contain device instance IDs,
container IDs, USB topology, local paths, timestamps, and driver information.
Recovery snapshots additionally contain a machine identifier and may include
exported vendor driver files. Keep these files private and intact for recovery.
Do not redact the only recovery copy or redistribute vendor driver packages.

Do not upload reports, validation results, logs, transcripts, exported drivers,
original downloaded packages, or your surrounding workspace. The supplied
`.gitignore` denies unlisted files by default. It cannot protect files already
tracked by Git, files forced into Git, screenshots, or files attached to issues.

## Shareable Diagnostics

Use `-Action Inspect -ShareSafe` to produce a separate allowlisted JSON summary.
It includes generic labels, diagnosis categories, numeric error codes, driver
versions, and aggregate observation results. It excludes device identifiers,
hardware IDs, names, paths, machine IDs, raw errors, and exact timestamps.
It is not a recovery snapshot. Device labels only apply to that output, not
to subsequent runs. Review even a share-safe summary before publishing it.

Only the generated JSON is intended for sharing. Shell history, transcripts,
screenshots, the command line, and PowerShell parameter-binding errors may expose
local paths or arguments. The script suppresses its own detailed CLI error in
ShareSafe mode, but cannot sanitize text generated by the shell before it runs.

## Public Packages

`Export-PublicPackage.ps1` copies only seven named source/documentation files into
a new directory and ZIP. It excludes all runtime data and `.git` history. It also
checks for common local identity markers, user-profile paths, MAC addresses,
GitHub tokens, and private-key headers. This is a guardrail, not a complete secret
scanner; manually review the archive before publication. Adding a source file
requires reviewing both the export allowlist and `.gitignore`.

Create a new repository from the clean export. Do not upload the development
workspace or push an older repository's history without separately reviewing it.
The export script does not create a remote repository, commit, push, sign into
GitHub, or change Git identity configuration.
